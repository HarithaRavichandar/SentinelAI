# Task 12.1.0 – Independent Evaluation Feasibility Audit

## Executive Summary
The SentinelAI repository does **not** contain a truly independent hold‑out dataset. The three Legacy masks (`train`, `val`, `test`) together partition every one of the 447,915 rows in the original capture, so no row remains completely untouched by the historical Legacy workflow. The Fresh masks cover a subset of the rows (excluding 8,909 conflict rows) but also overlap the Legacy validation and test partitions. Consequently, a retrospective split of the existing data cannot serve as an untouched benchmark for the already‑trained models. This audit retains the useful inventory and exposure information, clarifies the limits of exact‑feature grouping, marks the provenance of the raw data as provisional, and recommends acquiring a genuinely separate dataset for final independent evaluation.

## Provenance
* **Raw acquisition** – The repository contains a CSV (`data/raw/CICFlowMeter_out.csv`) that appears to be the output of the CICFlowMeter tool applied to a network‑capture dataset. No definitive documentation confirming that the source is the CIC‑IDS 2017 dataset is present in the repository; therefore the precise provenance is **PROVISIONAL / UNKNOWN**.
* **Feature extraction** – `src/sentinelai/features/preprocessing.py` (lines 12‑48) builds a 76‑feature vector per flow.
* **Duplicate detection** – `src/sentinelai/data/split.py` defines `group_exact_duplicates()` (lines 78‑105) which groups rows with identical feature vectors.
* **Mask generation** – Legacy masks are produced by `scripts/create_legacy_masks.py` (lines 22‑59). Fresh masks are generated by `scripts/create_fresh_masks.py`, which first removes the conflict mask (rows where duplicate groups contain mixed labels) before a stratified split (lines 35‑71).
* **Policy calibration** – `scripts/calibrate_fresh_policy.py` loads the Fresh validation mask (line 27) and fits a threshold; calibrated parameters are saved to `src/sentinelai/triage/calibrated_params_fresh.json` (line 58).

## Group‑Level Separation Feasibility
The exact‑feature grouping implemented in `src/sentinelai/data/split.py` guarantees that rows with identical feature vectors stay together across partitions, preventing **feature‑level** leakage. However, this does **not** establish independence at higher‑level dimensions such as:
* Network session or flow identifiers
* Source / destination hosts
* Capture period or attack campaign
* Original PCAP file or source collection
Therefore, identical‑feature grouping alone cannot be used to claim capture‑level independence.

## Recommendation
**Primary recommendation:** Acquire a genuinely separate dataset (Options B, C, or D) for the final independent evaluation. This provides a defensible benchmark that has never been inspected during model development.

*Retrospective analysis* (Option A) can still be useful for exploratory experiments, but any results must be clearly flagged as having historical exposure and cannot be presented as evidence of generalisation to unseen data.

## Risks & Limitations
* **Historical bias** – The existing CIC‑IDS‑derived data reflects a specific network topology and traffic mix; re‑splitting cannot eliminate this bias.
* **Feature‑level leakage** – Exact‑duplicate grouping prevents duplicate‑feature leakage but does not guard against higher‑level correlations.
* **Label alignment** – External datasets may use different attack taxonomies; mapping to the current 10‑class scheme may introduce ambiguity.
* **Resource constraints** – Acquiring and preprocessing new captures requires storage, compute, and labeling effort.

## Next Steps (Task 12.1.1)
1. **Select a source** for an independent dataset (e.g., CIC‑IDS 2020, UNSW‑NB15, or an in‑house capture).
2. **Create a preprocessing adapter** that transforms the raw capture into the 76‑feature schema used by SentinelAI (reuse `src/sentinelai/features/preprocessing.py` where possible).
3. **Define a label‑mapping strategy** if the new dataset uses a different taxonomy.
4. **Generate fresh train/validation/test masks** using the existing `src/sentinelai/data/split.py` utilities, ensuring duplicate‑group integrity.
5. **Document** the full pipeline and provenance in a new report `reports/task_12_1_1_independent_dataset_creation.md`.
6. **Run a baseline evaluation** on the newly created independent split to establish a reference performance.
